# XSS · 原理笔记

> Payload 见 [payload.md](payload.md) ｜ 做题记录见 [做过的题.md](做过的题.md)

## 一句话本质

**用户输入被输出到 HTML 页面时没有做上下文相关的编码**，于是浏览器把它当成代码执行。核心不是"输入里有 `<script>`"，而是"输出位置允许代码"。

## 三种类型

| 类型 | 数据流 | 特点 | 常见位置 |
| --- | --- | --- | --- |
| 反射型 | 请求 → 立即回显 | 需要诱导点击，payload 在 URL 里 | 搜索框、错误提示、跳转参数 |
| 存储型 | 请求 → 存库 → 其他用户访问时触发 | 危害最大，可蠕虫化 | 留言、昵称、评论、个人签名 |
| DOM 型 | 完全在前端 JS 里 | 服务端日志看不到 payload | `innerHTML`、`document.write`、`eval`、`location.hash` |

## 输出位置决定 payload 形态（最关键的一步）

**先看注入点落在 HTML 的哪个位置，再决定怎么闭合。**

| 输出位置 | 例子 | 需要的写法 |
| --- | --- | --- |
| HTML 标签之间 | `<div>这里是输出</div>` | `<script>alert(1)</script>` |
| HTML 属性值内（双引号） | `<input value="输出">` | `"><script>alert(1)</script>` |
| HTML 属性值内（单引号） | `<input value='输出'>` | `'><script>alert(1)</script>` |
| 未加引号的属性 | `<input value=输出>` | `onmouseover=alert(1) ` |
| `<script>` 标签内（字符串） | `var a="输出";` | `";alert(1);//` |
| `<script>` 标签内（非字符串） | `var a=输出;` | `alert(1)` 或 `1;alert(1)` |
| 事件属性内 | `<a href="javascript:输出">` | `alert(1)` 或 `javascript:alert(1)` |
| CSS 内 | `<style>输出</style>` | `</style><script>alert(1)</script>` |
| 注释内 | `<!-- 输出 -->` | `--><script>alert(1)</script>` |

## 检测方法

1. **看反射**：提交一个唯一字符串（如 `xss123test`），在页面源码里搜它，确认落在哪个上下文。
2. **手工构造**：按上表选形态，最省事的起点是 `"><img src=x onerror=alert(1)>` 和 `'><script>alert(1)</script>`。
3. **看长度限制与过滤**：被截断就缩短 payload；被过滤就把关键字拆开（见 payload.md 的绕过表）。
4. **看 CSP**：响应头有 `Content-Security-Policy` 时，内联脚本可能被禁，需要找允许的源或 JSONP 端点。
5. **DOM 型**：看前端代码里有没有把 `location.search` / `location.hash` / `document.referrer` 直接塞进 `innerHTML`。

## 危害升级链（证明危害时按这个走）

```
alert(1) 弹框  →  读取 Cookie (document.cookie)  →  以受害者身份发请求 (CSRF+)
→  读取页面敏感数据  →  键盘记录 / 钓鱼表单  →  配合 CSRF 改密码 / 打后台
```

- **HttpOnly** 为真时 `document.cookie` 读不到会话 Cookie，此时改走「以受害者身份操作」的路线（打后台、改邮箱）。
- 后台 XSS 打管理员（BOT）是 CTF 里最常见的得分点：需要 payload 把 `document.cookie` 或页面内容外带到自己服务器。

## 防御与已知绕过

| 防御 | 是否足够 | 绕过思路 |
| --- | --- | --- |
| 输出时按上下文编码 | ✅ 治本 | 编码位置必须对：HTML 实体 ≠ JS 编码 ≠ URL 编码 |
| `htmlspecialchars()` | ✅（注意第二个参数） | PHP 8.1+ 默认 `ENT_QUOTES \| ENT_SUBSTITUTE`；老版本要显式写 `ENT_QUOTES`，否则单引号不转义 |
| 过滤 `<script>` | ❌ | `onerror` / `onload` / `<svg>` / `<iframe srcdoc>` 等大量替代 |
| 过滤 `alert` | ❌ | `confirm`、`prompt`、`print`、`(function(){})()`、`top['al'+'ert'](1)` |
| 黑名单关键字 | ❌ | 大小写、HTML 实体编码、`%0a` 分隔、注释插入 |
| HttpOnly Cookie | ⚠️ 只防偷 Cookie | 照样能发请求、改数据 |
| CSP | ✅ 若配置严格 | `unsafe-inline`、白名单域有 JSONP/上传点、`nonce` 可猜 → 都能被打穿 |
| 输入过滤（而非输出编码） | ❌ | 存储型数据可能从别的入口写入，编码才是正确位置 |
