# SQL 注入 · 原理笔记

> Payload 见 [payload.md](payload.md) ｜ 做题记录见 [做过的题.md](做过的题.md)

## 一句话本质

**用户可控的输入被当作 SQL 语句的一部分拼接执行**，导致攻击者能改写原本的查询语义。根因永远是「数据」和「代码」没有分离——字符串拼接是万恶之源。

## 触发条件

- 输入被拼接进 SQL 语句（`"SELECT * FROM users WHERE id=" + id`）
- 拼接后的语句被数据库执行
- 报错信息、页面内容、响应时间、外带通道中至少有一条能回显差异

## 注入点位置

| 位置 | 示例 | 注意 |
| --- | --- | --- |
| GET/POST 参数 | `?id=1` | 最常见 |
| Cookie / Header | `User-Agent`、`X-Forwarded-For` | 常被日志功能带进 SQL |
| ORDER BY / LIMIT 后 | `?sort=name` | **不能**用预编译占位符，只能白名单 |
| 表名 / 列名 / IN 子句 | `?table=users` | 同上 |
| 二次注入 | 注册时存恶意用户名，改密码时被拼进 SQL | 入库时转义、出库时未转义 |

## 分类与判断顺序

实测时按这个顺序试，**能联合就联合，不能就报错，再不能就盲注**：

| 类型 | 特征 | 判断方法 |
| --- | --- | --- |
| 联合查询 (UNION) | 页面直接回显查询结果 | 先 `ORDER BY n` 探列数 |
| 报错注入 | 页面回显数据库报错 | `and extractvalue(...)` 有回显即中 |
| 布尔盲注 | 无回显，但真假条件导致页面差异 | `and 1=1` vs `and 1=2` 对比 |
| 时间盲注 | 连页面差异都没有 | `and sleep(5)` 看响应时间 |
| 堆叠注入 | 支持多语句（MySQL + PDO 模拟预处理 `;`） | `;select 1` 是否执行 |
| 带外 (OOB) | 全盲且无时间差 | DNSLog / HTTP 外带 |

## 数据库差异表

| 特性 | MySQL | MSSQL | Oracle | PostgreSQL |
| --- | --- | --- | --- | --- |
| 注释 | `#`、`-- `（后跟空格）、`/**/` | `-- `、`/**/` | `-- `、`/**/` | `-- `、`/**/` |
| 字符串拼接 | `concat(a,b)` | `a+b` | `a\|\|b` | `a\|\|b`、`concat()` |
| 版本函数 | `version()`、`@@version` | `@@version` | `select banner from v$version` | `version()` |
| 当前库 | `database()` | `db_name()` | `select name from v$database` | `current_database()` |
| 元数据表 | `information_schema.tables` | `sysobjects`、`sys.columns` | `all_tables`、`all_tab_columns` | `information_schema.tables` |
| 拼接多行 | `group_concat()` | `stuff()+for xml path` | `wm_concat()`、`listagg()` | `string_agg()` |
| 延时 | `sleep(n)`、`benchmark()` | `waitfor delay '0:0:5'` | `dbms_pipe.receive_message()` | `pg_sleep(n)` |
| 无 from 也能查 | ✅ `select 1` | ✅ | ❌ 必须 `from dual` | ✅ |

## 关键函数速记（MySQL，最常考）

- `database()` 当前库、`user()` 当前用户、`version()` 版本
- `group_concat()` 多行合并成一行，省去逐字符跑的功夫
- `substr(s,pos,len)` / `ascii()` / `hex()` 逐字符提取
- `extractvalue(xml, path)` / `updatexml(xml, path, val)` 报错回显（受 `||` 与长度限制，报错信息最长约 32 字符）
- `information_schema.tables` / `.columns` 拿表名列名
- `load_file()` 读文件（需要 `FILE` 权限 + `secure_file_priv` 允许）
- `into outfile` / `into dumpfile` 写文件（需要 `FILE` 权限 + 可写目录 + `secure_file_priv`）

## 检测步骤（手工，不用工具）

```bash
# ① 加单引号看是否报错
?id=1'
# ② 真假对比：两者返回不同则存在布尔注入
?id=1 and 1=1
?id=1 and 1=2
# ③ 探列数（二分更快）
?id=1 order by 5 -- -
# ④ 联合查询定位回显位
?id=-1 union select 1,2,3 -- -
# ⑤ 取信息
?id=-1 union select 1,database(),version() -- -
```

## 防御与已知绕过

| 防御 | 是否足够 | 绕过思路 |
| --- | --- | --- |
| 预编译 / 参数化查询 | ✅ 治本 | 表名列名、ORDER BY 后不能参数化，需白名单 |
| `addslashes` / `mysql_real_escape_string` | ❌ | 宽字节注入（GBK 下 `%df'`）、数字型注入无需引号 |
| `magic_quotes_gpc` | ❌ | 已废弃，且只处理 GET/POST/COOKIE |
| 过滤关键字 `select`/`union` | ❌ | 大小写、`sel/**/ect`、`%0a` 内联注释、双写 |
| WAF | ⚠️ | 依靠语法变形绕过；不要依赖 |
| 关闭报错回显 + 统一错误页 | ⚠️ 仅提高门槛 | 时间盲注、布尔盲注、OOB 照样可用 |
