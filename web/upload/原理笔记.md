# 文件上传 · 原理笔记

> Payload 见 [payload.md](payload.md) ｜ 做题记录见 [做过的题.md](做过的题.md)

## 一句话本质

**服务端把用户上传的文件按"可执行资源"保存到了 Web 可访问目录**，于是上传的文件被解析器当代码执行。漏洞成立需要同时满足三个条件：

1. 文件**内容**可控（能写入 PHP/ASP/JSP 代码）；
2. 文件**路径与文件名**可控（能决定后缀、能落到 Web 目录）；
3. 服务器**会解析**该文件（后缀映射到解释器，或结合解析漏洞/包含漏洞）。

**三者缺一，上传本身就不算漏洞。** 做题时按这三个条件逐个找突破口。

## 常见校验点与对应的突破方向

| 校验点 | 服务端怎么做 | 突破方向 |
| --- | --- | --- |
| 前端 JS 校验 | `accept`、`onsubmit` 检查后缀 | 直接抓包改包（前端校验等于没有） |
| Content-Type | 检查 `image/png` 等 MIME | 抓包改 `Content-Type` |
| 文件后缀 | 黑名单或白名单 | 黑名单：找漏掉的解析后缀；白名单：找解析器差异、`%00`、大小写、双后缀 |
| 文件头/幻数 | 检查 `GIF89a`、`\x89PNG` | 加文件头做"图片马" |
| 文件内容 | 查 `<?php` 等关键字 | 短标签、大小写、`<script language=php>`、注释混淆 |
| 文件名 | 过滤 `../`、特殊字符 | 编码变形、截断、超长文件名 |
| 目录 | 重命名、随机化、存到非 Web 目录 | 配合文件包含、目录穿越、软链接 |
| 二次处理 | 压缩图片、缩放 | 图片马被重编码后可能失效，需结合其他点 |

## 解析漏洞（"有后缀也照样执行"）

| 环境 | 现象 | 说明 |
| --- | --- | --- |
| Apache 多后缀 | `shell.php.jpg` 被当作 PHP | 从右往左找可识别的后缀 |
| Apache `.htaccess` | 上传 `.htaccess` 改写解析规则 | 与自身配置允许 `AllowOverride` |
| Nginx + PHP-FPM | `/upload/x.jpg/x.php` 被解析 | `cgi.fix_pathinfo=1` 的经典问题 |
| Nginx 空字节 | `x.php%00.jpg` | 老版本 |
| IIS 6.0 | `x.asp;.jpg`、`x.asp/x.jpg` | 分号与目录解析 |
| IIS 7.x | `x.jpg` + 配置错误 | FastCGI 配置不当导致任意后缀解析 |
| PHP 配置 | `AddType application/x-httpd-php .png` | `.user.ini` 的 `auto_prepend_file` 也能利用 |

## 上传之后怎么执行

| 情况 | 做法 |
| --- | --- |
| 有上传目录 URL | 直接访问 `http://目标/uploads/shell.php` |
| 文件被重命名 | 响应中通常会返回新路径，或结合遍历/包含 |
| 上传目录不可访问 | 配合 **文件包含 (LFI)**：`?file=uploads/shell.jpg` |
| 只能传图片 | 图片马 + 包含，或找解析漏洞 |
| 有杀软/WAF 查内容 | 用免杀技巧（拆分关键字、`<?=` 短标签、编码） |

## 防御

| 做法 | 说明 |
| --- | --- |
| 白名单后缀 + **重命名** | 服务端自己生成随机文件名与后缀，别信客户端 |
| 落到非 Web 目录 | 上传目录不允许执行脚本（Nginx/Apache 配置 `deny`） |
| 校验真实文件类型 | 用 `getimagesize()`、`finfo`，不只信 Content-Type |
| 二次渲染/压缩 | 破坏内嵌代码，但要注意不能只看这一层 |
| 禁止 `AllowOverride` | 防 `.htaccess` 提权 |
| 独立存储 + 签名 URL | 治本方向 |
| 上传目录与解析分离 | 存文件的服务不解析脚本 |
