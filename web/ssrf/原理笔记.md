# SSRF 服务端请求伪造 · 原理笔记

> Payload 见 [payload.md](payload.md) ｜ 做题记录见 [做过的题.md](做过的题.md)

## 一句话本质

**服务端拿用户提供的地址去发起请求**，攻击者就能借服务器的身份和网络位置，访问自己够不到的内网与本地服务。漏洞点不在"能不能访问外网"，而在**服务端信任了这个 URL**。

## 常见入口

| 功能 | 典型参数 | 说明 |
| --- | --- | --- |
| 图片/头像加载 | `?url=`、`?img=`、`?src=` | 最常见 |
| URL 预览 / 分享抓取 | `?link=`、`?target=` | |
| Webhook 配置 | `?callback=`、`?notify=` | 可打内网 |
| 文件下载 / 导入 | `?file=`、`?download=` | 配合 `file://` 直接读文件 |
| PDF / 截图生成服务 | 提交 URL 生成图片 | 常存在且防护弱 |
| 代理 / 翻译 / RSS 解析 | `?proxy=`、`?feed=` | |
| XML 外部实体 (XXE) | DOCTYPE 里的 SYSTEM URL | 本质也是服务端发请求 |

## 三种回显程度

| 类型 | 现象 | 打法 |
| --- | --- | --- |
| 完全回显 | 响应体直接返回目标内容 | 最简单，直接读 |
| 半回显 | 只回显状态/长度/报错 | 靠报错差异与长度判断端口与内容 |
| 盲 SSRF | 什么都没有 | 时间差、DNSLog 外带、错误信息差异 |

## 危害链（由浅入深）

```
探测内网存活与端口  →  读本地文件 (file://)  →  访问内网未授权服务（Redis/MySQL/ES/后台）
→  利用 Gopher 构造任意 TCP 流量打内网  →  拿云主机元数据凭据  →  接管云资源
```

## 云元数据地址（CTF 与实战的高价值目标）

| 云厂商 | 地址 | 注意 |
| --- | --- | --- |
| AWS | `http://169.254.169.254/latest/meta-data/` | IMDSv2 需要先 PUT 拿 token |
| AWS IAM 凭据 | `http://169.254.169.254/latest/meta-data/iam/security-credentials/<role>` | 直接给 AccessKey |
| 阿里云 | `http://100.100.100.200/latest/meta-data/` | |
| 腾讯云 | `http://metadata.tencentyun.com/latest/meta-data/` | |
| 华为云 | `http://169.254.169.254/latest/meta-data/` | |
| GCP | `http://metadata.google.internal/computeMetadata/v1/` | **必须带** `Metadata-Flavor: Google` 头，SSRF 若不能自定义头就打不了 |

## 协议族（不只是 http）

| 协议 | 用途 |
| --- | --- |
| `http` / `https` | 常规探测与访问内网 Web |
| `file` | 读本地文件：`file:///etc/passwd` |
| `gopher` | **构造任意 TCP 数据包**，打 Redis / MySQL / FastCGI / SMTP 的利器 |
| `dict` | 探测端口与服务信息 |
| `ftp` / `sftp` / `tftp` | 读文件、探测 |
| `ldap` | 打内网 LDAP |
| `jar` | Java 环境下可加载远程 jar（老漏洞） |

> `gopher://` 的 payload 是 URL 编码的裸 TCP 数据，一个字节都不能错——建议用脚本生成，别手写。

## 检测要点

1. **看有没有回显**：先打自己的外网服务器（`http://<你的服务器>:<端口>`），看有没有访问记录。
2. **DNSLog 验证盲打**：请求 `http://xxx.dnslog.cn`，看 DNS 记录是否出现——有记录就说明真的发出了请求。
3. **试协议**：`file://`、`dict://`、`gopher://` 逐个试。
4. **试内网地址变形**（绕过黑名单，见 payload.md）。
5. **试 302 跳转**：自己服务器返回 302 指向 `http://127.0.0.1`，绕过"只检查第一次请求"的防护。

## 防御与已知绕过

| 防御 | 是否足够 | 绕过思路 |
| --- | --- | --- |
| 黑名单 `127.0.0.1` | ❌ | 变形地址一大堆（见 payload.md） |
| 黑名单内网网段 | ❌ | 进制变形、DNS 解析到内网、IPv6、跳转 |
| 只允许 http/https | ⚠️ | 302 跳到 `file://`/`gopher://`；协议大小写混写 |
| 校验域名白名单 | ⚠️ | 用白名单域名做开放跳转；`@` 解析差异 |
| 解析域名后校验 IP | ✅ 较可靠 | 但要注意 **DNS Rebinding**（第一次解析合法、第二次指向内网） |
| 禁止跳转 (follow redirect=false) | ✅ | 配合 IP 校验才完整 |
| 独立网段 / 出网白名单 | ✅ 治本 | 服务端本身不允许访问内网 |
| 统一出口代理并做审计 | ✅ | |

**正确做法**：解析域名 → 拿到 IP → 校验 IP 是否为内网/保留地址 → **直接连这个 IP**（避免二次解析），并禁止跳转。
